# Attribute a loss to the thing that caused it, with the predicate that measures what happened

**Context:** CORE-006 replaced a failing prediction with a consequence check: after applying a page's redactions, re-read the page and refuse if an object that was not the target lost characters. The check passed an independent review and a planted-loss test, and its accept-list -- the one legitimate exception, "a loss no rectangle could avoid" -- read `any(_same_line(target, box) for _, target in redactions)`: is *any* replacement on this page's target co-located with the object that lost characters?
**Problem:** the second signer reproduced a REAL Major from that one line. Every fixture drove exactly one replacement, and one-replacement pages cannot show it: with two replacements on the page, *an unrelated replacement elsewhere on the lost line* answered the question yes, and a refusal became a warning whose text -- "its ink is drawn in the same place" -- was false about an object that shares ink with nothing. At 12 pt Helvetica and 0.6 em leading, replacing the tight block's target alone refused the document; replacing it *and* a value drawn to the right on the next line converted, dropped the neighbour, and reported it as accepted. The verdict of a document depended on a replacement with no geometric relationship to the loss, and multi-replacement pages are the normal case. Fixing it uncovered two more defects, each invisible to the checks that existed:
**Solution:** **(1) Ask which actor caused the outcome, not whether any actor could have.** A loss is excused only by a rectangle that *removed that glyph* **and** whose target shares the lost object's line; and *every* lost character has to be excused that way, so an object cannot be half-excused through the middle of a span. Requiring it per glyph means the comparison needs the vanished characters' *positions*, which changed the shape of the data the check carries: the loss is reported as glyph keys, not as a character string. **(2) Two predicates that look alike answer different questions.** Attribution asks what the redactor *did* -- `apply_redactions` removes a character at the measured 10.0% of its box, no margin. The trim asks what is *safe* -- the same measurement plus a small margin (12%). Reusing the safety predicate for attribution refused `backend/tests/data/sample.pdf` page 1 for a glyph the redactor had actually removed, and **the integration suite caught it while no unit row could**: synthetic fixtures do not sit on the margin, so the distinction is invisible to them. Two constants now exist, each named for the question it answers. **(3) Not every vanished glyph is a loss.** With attribution fixed, the same page still refused -- for a **space**. The lone whitespace-only span between `Visa` and `ending in 3777` disappears when PyMuPDF rewrites the line it touches, with a zero-width overlap against *every* rectangle on the page: nothing removed it, the rewrite did. A consequence check has to define what counts as content, or it refuses convertible documents over characters no reader can see. **(4) Aim the row at the defect.** Neutralising the fixed line (M8) turns exactly one row red -- the row written from the reproduction -- which is what makes the other rows' silence meaningful rather than suspicious.
