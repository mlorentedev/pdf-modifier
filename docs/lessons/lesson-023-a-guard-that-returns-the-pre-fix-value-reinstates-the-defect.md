# A guard that falls back to the value from before the fix reinstates the defect — silently

**Context:** CORE-001 fixed a destructive defect: replacing a span inside a multi-line block dropped the two lines after it, because `apply_redactions` removes every glyph that *intersects* the rectangle and a tight block's consecutive line boxes overlap by 1.6 pt. The fix trimmed the redaction rectangle away from the neighbours, its own tests went green, the real receipt came out whole, and it was merged. An independent review then returned **FAIL** with a reproduced Blocker — and it was right.
**Problem:** the trim changed **y** only, because every neighbour the reproduction had produced was above or below. The shape the review built had the neighbour **beside** the target: one receipt line drawn as two text objects — a label span and a value span in a different colour, heart of every key-value line. A same-line neighbour carries the target's *own* `y0`, so the y-trim dragged the rectangle's `y1` up onto its `y0`, the rectangle collapsed to area 0, and the guard — written to stop an empty rectangle reaching the redactor — did the only thing it contained: `return fitz.Rect(rect)`, **the raw, unfitted rectangle**. The defect was restored by the code that existed to remove it, and every one of the six fixture rows drew its lines as a single object, so the suite could not generate the shape that would have failed. Two things had been mistaken for one: "the fix works" and "the fix works in the only shape I built".
**Solution:** three rules, in the order they matter. **(1) A guard's fallback is a decision, not a no-op.** Before writing one, read what it returns and ask what that value *means* to the caller: if it is the value the fix replaced, the fix is conditional on the guard never firing — and the guard said nothing when it did. An area of zero is not a small rectangle, it is a fitting **failure**: report it (a typed error, a warning the caller can see), never fall through to the pre-fix value. **(2) Fix along the axis the conflict is on.** A neighbour that shares the rectangle's vertical band is *beside* it and only x separates them; one in another band is above or below and only y does. A one-axis fix is a claim that every conflict is on that axis — a claim the code cannot check and the tests will not contradict if they build only one shape. **(3) The fixture that found the defect does not test the fix.** Each new *shape* of input is a new test: vary the structure (one object vs two per line), not only the values (three replacement sizes) — and re-derive the shape from the failure mode rather than reusing the reproduction that happened to fail first. Corollary earned in the same round: the obvious replacement fallback ("return a tiny rectangle instead") was measured before being written, and removes **no glyph at all** at 0.02 pt — it would have left the original text sitting under the replacement. A fallback is a candidate like any other: verify it, or fail loudly.
