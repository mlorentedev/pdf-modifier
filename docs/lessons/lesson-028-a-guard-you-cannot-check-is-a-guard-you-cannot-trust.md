# A guard that predicts is a guard you cannot check; verify the consequence instead

**Context:** CORE-001 repaired a destructive defect — a replacement dropped the lines after it, because `apply_redactions` removes every glyph a rectangle *intersects* and a tight block's line boxes overlap. The repair was a **prediction**: shrink the rectangle away from the neighbours, keep the shrink only if the object being replaced is still covered, refuse when no rectangle satisfies both. Four independent adversarial review rounds each FAILed on a real defect, and every one was the same prediction being wrong in a geometry nobody had built yet: a neighbour on the same line collapsed the rectangle; an overlapping neighbour let the first characters of the old value survive; a block tighter than its glyph height lost a line in silence; a page-sized object drawn under the text was mistaken for the object being replaced, and span order decided whether the page converted at all. Each fix was correct for the shape it was written for and blind to the next.
**Problem:** the prediction had no finite argument for correctness, and every round of review was a search for a geometry it had not considered — with the losses landing on *content*, silently, which is the one outcome the whole task existed to prevent. Worse, the checks around it were shaped like the prediction: they asked "is the rectangle I am about to draw safe?", a question whose answer is only as good as the model behind it. What no round had was a check on the **outcome** — did anyone actually lose characters? — which is decidable by reading the artefact and needs no model at all.
**Solution:** **(1) When a guard cannot be argued, guard the consequence.** After the redaction, re-read the page's text and compare it with the text before: every character that vanished must belong to an object the operation was *allowed* to modify. That sentence is the whole check, it holds for any geometry, and it is decidable from the file — no geometry, no prediction, no case list. The prediction stays as an optimisation that reduces how often the check has to refuse, demoted from *the safety mechanism* to *a way to keep documents converting*. **(2) Choose the comparison unit to match the failure mode.** Lines of extracted text cannot see the failure: a partially surviving object comes back as a shorter object, and one lost character inside a line reads as "a line changed". Text objects cannot either: a redaction re-emits what it touched, sometimes split differently, and the target's own text is the one thing that is *supposed* to change. The unit that works is the **glyph, keyed by character and position** — what was drawn where, and is it still drawn there. **(3) A check that has never fired is a green check that reads nothing.** The consequence check is exercised by *planting* the defect it exists for (the fitter is monkeypatched to return the raw rectangle) and asserting the refusal. **(4) The old rows are the acceptance test for the new guard**: the first implementation of the check over-refused — it treated every object the rectangle reached as acceptable — and the pre-existing rows caught it within one run. **(5) Order the work so the failing row comes first.** The row that opened the core file was the reproduced silent loss at 0.60 em, and it had to be shown failing *for the intended reason*: the first RED reported losses at leadings the fitter is provably safe at, because reused test machinery hard-coded a different fixture's target line. A row that fails for the wrong reason is not evidence, it is a second defect.
